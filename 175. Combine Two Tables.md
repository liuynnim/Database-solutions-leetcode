# Intuition
<!-- Describe your first thoughts on how to solve this problem. -->
The problem asks us to list all people along with their addresses.  
Since the output does not require `addressId`, we can eliminate this column early.  
By projecting only the necessary attributes (`personId, firstName, lastName` from **Person** and `personId, city, state` from **Address**), we reduce the size of intermediate results and avoid unnecessary data processing.
# Approach
<!-- Describe your approach to solving the problem. -->
We apply two key optimization principles from relational algebra:

1. **Projection Pushdown (π):**  
   Select only the required columns before performing the join. This reduces the amount of data carried through the query plan.

2. **Left-Deep Join Tree:**  
   Start with the base relation (**Person**) and join it with filtered **Address**.  
   This strategy minimizes intermediate relation size and memory usage compared to bushy join trees.

The query uses a **LEFT JOIN** because we must include all people, even those without an address (with `NULL` values for city/state).
# Complexity
- Time complexity: 
With indexes on `personId`, the join runs in approximately **O(n + m)**, where `n` = number of rows in Person and `m` = number of rows in Address.
Without indexes, worst-case complexity could be **O(n × m)**.

- Space complexity: 
**O(n + m)** for intermediate results, but reduced compared to a full Cartesian product thanks to projection pushdown.
<!-- Add your space complexity here, e.g. $$O(n)$$ -->

# Code
```mysql []
SELECT p.firstName, p.lastName, a.city, a.state
FROM p
LEFT JOIN (SELECT personId, city, state FROM Address) a
ON p.personId = a.personId
```
