# Intuition
The key idea is to define what "activity" means in this context. A single user can have multiple `activity_type` entries or multiple `session_id` values in one day. Since we only care about whether a user was active on a given day, we should count **unique users per day** and ignore both `activity_type` and `session_id`.

# Approach
- Use a `WHERE` clause to restrict the data to the last 30 days ending on `'2019-07-27'`.
- The condition `BETWEEN DATE_SUB('2019-07-27', INTERVAL 29 DAY) AND '2019-07-27'` ensures we capture all records from `'2019-06-28'` through `'2019-07-27'`.
- Group the results by `activity_date` to compute daily statistics.
- Apply `COUNT(DISTINCT user_id)` to count each user only once per day.

# Complexity
- **Time complexity:**  
  The query scans all records within the 30-day window and groups them by date. This results in **O(n)** time complexity, where `n` is the number of records in the filtered range.

- **Space complexity:**  
  For each day, we need to store the set of distinct user IDs. The worst case is proportional to the number of unique users on the busiest day, so **O(u)**, where `u` is the maximum number of distinct users in a single day.

# Code
```mysql
SELECT activity_date AS day, COUNT(DISTINCT user_id) AS active_users
FROM Activity
WHERE activity_date 
BETWEEN DATE_SUB('2019-07-27', INTERVAL 29 DAY) 
    AND '2019-07-27'
GROUP BY activity_date;
